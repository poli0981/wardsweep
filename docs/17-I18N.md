## Architecture

The broker is **language-neutral**. It never emits user-facing prose. Every
message crossing IPC is a key plus arguments:

```jsonc
{ "message_key": "err.service.locked", "args": { "service": "vgk", "pid": 4 } }
```

The UI resolves keys against `.resx`. Consequences:

- Adding a locale requires **no broker change**
- The CLI resolves the same keys from an embedded table, so CLI and UI say the
  same thing in the same words
- Logs are written with keys *and* resolved English, so a log file from a
  Vietnamese user is still readable by a maintainer

## Key naming

```
<area>.<subject>.<detail>
```

```
scan.mode.audit
scan.mode.audit.desc
plan.tier.review
plan.blocked.refcount            "{ac} is still required by {games}"
err.service.locked
err.catalog.signature_invalid
confirm.apply.title
confirm.apply.games_irreversible
quarantine.expires_in            "Expires in {days} days"
```

No key is reused across areas even when the English text matches — the same
English word frequently needs different Vietnamese depending on context.

## Formatting rules

- **Never concatenate** translated fragments. Full sentences with named
  placeholders only.
- Placeholders are named (`{service}`), never positional, so translators can
  reorder freely.
- Counts use `.zero` / `.one` / `.other` variants even where English needs only
  two, so plural-less languages are not forced into English grammar.
- Dates and numbers use `CultureInfo.CurrentUICulture`. Never hand-formatted.
- Sizes: `1.2 GB` in `en`, `1,2 GB` in `vi`. Use `ByteSize` with the current
  culture, not string interpolation.

## Vietnamese specifics

- Diacritics throughout. The UI font stack must render Vietnamese correctly —
  verify Segoe UI Variable coverage, fall back to Inter if any glyph fails.
- Vietnamese runs roughly 15–25 % longer than English. Layouts use `Auto` sizing
  and wrap; no fixed-width buttons sized to English text.
- Technical terms stay in English where that is the working vocabulary:
  *driver*, *service*, *registry*, *anti-cheat*, *kernel*. Translating these
  makes the tool *harder* for the Vietnamese users who need it.
- Warning text is translated fully and carefully. If a user only ever reads one
  string in their own language, it should be the apply confirmation.

## Untranslated by design

- File paths, registry keys, service names, driver filenames
- Catalog `id` values
- Log level names, exit codes, error codes (`E_SERVICE_LOCKED`)
- Anti-cheat and game display names — these are proper nouns
- Everything in `docs/` — English, per open-source convention

## Build enforcement

CI fails on:

- A key present in `Strings.resx` but missing from a shipped locale
- A key present in a locale but absent from the source
- Placeholder mismatch between source and translation (`{service}` in one,
  `{svc}` in the other)
- A hardcoded user-facing string literal in XAML or ViewModel code — caught by a
  Roslyn analyser rule, not by review

## Pseudo-localisation

`--ui-culture=qps-ploc` renders every string as accented, 40 % longer text
wrapped in brackets. Any string that appears unmodified is hardcoded; any
layout that breaks will break in Vietnamese. Run before every release.
