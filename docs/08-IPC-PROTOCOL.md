# 08 — IPC Protocol

## Transport

Named pipe, message mode, one client, **`FILE_FLAG_OVERLAPPED`**.

```
\\.\pipe\wardsweep-{session-guid}
```

Session GUID is generated by the UI and passed to the broker on the command
line, so the pipe name is unpredictable and per-launch.

Overlapped is not a preference. A synchronous handle serialises the two
directions: spike [`S3`](../spikes/S3-RESULT.md) measured a 15-byte write into a
64 KiB buffer taking 2 735 ms while a `ReadFile` was pending on the same handle,
against 0 ms with nothing outstanding. Streaming `ScanBatch` while remaining able
to receive `ScanCancel` — which [`09`](09-UI-SPEC.md) promises as "always
available and immediate" — is impossible without it.

### Security

- Pipe created by the **broker** with an explicit DACL: `SYSTEM` and
  `Administrators` full control, plus the launching user's SID. No `Everyone`.
- `PIPE_REJECT_REMOTE_CLIENTS` set. Local only.
- Created with `FILE_FLAG_FIRST_PIPE_INSTANCE`. Without it, a process that
  guesses the name creates another *instance* and silently takes the next
  connection; with it, a name already in use is a hard startup failure. This is
  what closes the window during the handover below, where the name is briefly
  unowned. Spike [`S3`](../spikes/S3-RESULT.md) confirmed the second creator gets
  `ERROR_ACCESS_DENIED`.
- Broker calls `GetNamedPipeClientProcessId`, resolves the image path, and
  verifies it matches the expected UI binary — same directory as the broker and
  the expected filename — before accepting any command. The session GUID is
  compared against the one echoed in `Hello`, **not** against the client's
  command line: reading another process's command line needs
  `NtQueryInformationProcess` or WMI and buys nothing, because a client that
  connected at all has already demonstrated it knows an unpredictable name.
  The Authenticode signature is checked **when one is present**, and its absence
  is not a rejection: releases are unsigned by design
  ([`14`](14-DISTRIBUTION-TRUST.md)), so requiring a signature here would mean
  the check never passes on a real build.
- The process id must be re-validated against `GetProcessTimes`. Ids are unique
  only while the process lives, and a client that exits between
  `GetNamedPipeClientProcessId` and `OpenProcess` can have its id reused; a
  process that started *after* the id was reported is not the one that connected.
- One client. **The refusal of a second client happens at this layer, not at the
  transport.** With `nMaxInstances = 1` a second connect does not fail — it
  blocks in `WaitNamedPipe` until an instance frees, and there is no way to
  refuse a waiter. The broker accepts, verifies, and disconnects.

Note what the DACL does and does not do. It excludes other users and remote
clients. It does **not** exclude a hostile process run by the same user, because
every process that user starts carries that SID. The client image check is what
defends there, and the two must not be conflated.

Verifying the DACL after creation means comparing against its **canonical**
form, not the string that was passed in. The kernel maps generic rights through
the object type's generic mapping at creation, so `GA` reads back as `FA` and
`GRGW` reads back as `0x12019F`; a readback compared against the requested SDDL
never matches.

## Framing

```
┌────────────┬─────────────────────┐
│ u32 LE len │ UTF-8 JSON payload  │
└────────────┴─────────────────────┘
```

Max frame 16 MiB. Larger payloads (full artifact trees) stream as multiple
`ScanBatch` events rather than one frame.

## Message envelope

```jsonc
{ "v": 1, "id": "req-0007", "type": "ScanStart", "payload": { } }
{ "v": 1, "id": null, "seq": 41, "type": "StageEvent", "payload": { } }
```

Responses echo `id`. Events use `id: null` and carry **`seq`**, a monotonic
counter over the events of one broker session. Commands and responses have no
`seq`.

`seq` exists so [reconnection](#reconnection) is possible at all: without it a
reconnecting UI cannot say where it got to, and the broker cannot know what to
replay. Added after spike [`S3`](../spikes/S3-RESULT.md).

## Commands — UI → broker

| Type | Payload | Response |
|---|---|---|
| `Hello` | `{ ui_version, session, resume_from }` | `HelloAck { broker_version, catalog_version, elevated, job_id, job_last_seq, job_finished, resumed_from }` |
| `ScanStart` | `{ mode: "audit" \| "orphan" \| "full", deep_fs: bool }` | `Ack` then `ScanBatch*` + `ScanComplete` |
| `ScanCancel` | `{}` | `Ack` |
| `PlanBuild` | `{ selected_game_ids[] }` | `PlanReady { plan_id, tree, blocked[] }` |
| `PlanPreview` | `{ plan_id, toggled_game_ids[] }` | `PlanReady` (recomputed refcounts) |
| `ApplyPlan` | `{ plan_id, approved_artifact_ids[], confirm_token }` | `Ack` then `StageEvent*` |
| `JobStatus` | `{ job_id }` | `JobState` |
| `JobResume` | `{ job_id }` | `Ack` |
| `Rollback` | `{ job_id, entry_ids[] \| "all" }` | `Ack` then `RollbackEvent*` |
| `QuarantineList` | `{}` | `QuarantineSummary` |
| `QuarantinePurge` | `{ job_id, confirm_token }` | `Ack` |
| `ReportExport` | `{ job_id, format }` | `ReportReady { path }` |
| `CatalogImport` | `{ toml_path, sig_path }` | `CatalogResult` |
| `Shutdown` | `{}` | closes |

### Deliberately absent

There is **no** `DeletePath`, `DeleteKey`, `StopService`, `RemoveAntiCheat`, or
any command that names a target directly. Every destructive command references
artifact IDs from a plan the broker built and holds in memory.

Consequence: even a fully compromised UI cannot express "delete `C:\Windows`" —
the vocabulary does not contain it. This is the main reason the command surface
is closed rather than generic.

### `confirm_token`

`ApplyPlan` and `QuarantinePurge` require a token the broker issued with the
plan, valid for 5 minutes, single use. Prevents a replayed or stale `ApplyPlan`
from executing against a plan the user has since modified.

## Events — broker → UI

| Type | Payload |
|---|---|
| `ScanBatch` | `{ findings[], scanned_count, elapsed_ms }` |
| `ScanProgress` | `{ phase, current, total }` |
| `ScanComplete` | `{ total, partial: bool, access_denied_paths[] }` |
| `StageEvent` | `{ job_id, stage, state, artifact_id?, message_key, args{} }` |
| `RebootRequired` | `{ job_id, pending_count }` |
| `NeedsUserAction` | `{ job_id, artifact_id, action_key, instructions_key }` |
| `RollbackEvent` | `{ job_id, entry_id, state }` |
| `JobComplete` | `{ job_id, status, residual_count, report_path }` |
| `Error` | `{ code, message_key, args{}, recoverable }` |

### Localisation

Events carry **`message_key` + `args`**, never rendered English prose. The UI
resolves keys against its `.resx` files. This keeps the broker language-neutral
and means adding a locale requires no broker change.

```jsonc
{ "type": "Error", "payload": {
    "code": "E_SERVICE_LOCKED",
    "message_key": "err.service.locked",
    "args": { "service": "vgk", "pid": 4 },
    "recoverable": true }}
```

## Backpressure

`ScanBatch` is capped at 500 findings per frame. The broker waits for the write
to complete before producing the next batch, so a slow UI throttles the scanner
rather than growing an unbounded queue. This is a deliberate part of the memory
budget — see [`10`](10-PERF-BUDGET.md).

## Reconnection

If the pipe drops mid-job the broker **continues**: it detects
`ERROR_BROKEN_PIPE` on its next write, leaves the job running, and returns to
`ConnectNamedPipe` on the same name.

The UI relaunches, reconnects using the same session GUID (persisted in
`%LOCALAPPDATA%\WardSweep\session.json`), and sends `Hello` with `resume_from`
set to the last `seq` it can account for. `HelloAck` returns a `JobState`
snapshot; streaming resumes at `resume_from + 1`.

The UI persists **the session GUID only**, not a running event position — at the
`ScanBatch` rates in [`10`](10-PERF-BUDGET.md) a write per batch is not
affordable. Its position after a crash comes from the `JobState` snapshot, and
`resume_from` is what makes reconnection exact rather than approximate.

If the broker is gone instead, the UI reads job state directly from SQLite in
read-only mode and offers resume or rollback. Spike
[`S3`](../spikes/S3-RESULT.md) confirmed this survives a force-killed writer in
WAL, DELETE and TRUNCATE journal modes, and returns current rather than stale
data even when the `-wal` and `-shm` files cannot be written. It also found that
`jobs.db` is **not self-contained** without its sidecars — hence the per-stage
`wal_checkpoint(TRUNCATE)`, so anything that copies the single file (a
diagnostics bundle, a backup) copies a database rather than a header.

## Versioning

`v` is the protocol version. Broker and UI must agree on the major version;
mismatch produces a clear "components out of sync, reinstall" message rather
than undefined behaviour. Velopack updates both together, so mismatch means
something went wrong.

## Testing

- Golden fixtures: every message type serialised and round-tripped in both
  languages, compared byte-for-byte
- Fuzz the frame reader (truncated length, oversized length, invalid UTF-8,
  deeply nested JSON)
- Impersonation test: a second process attempting to connect must be refused
